# Five researched offline import foundations

Official documentation was reviewed on 28 October 2026. These links establish documented mechanisms and constraints, not successful target imports. Plan status remains `OFFLINE_FIXTURE_TARGET_CONFIGURATION_REQUIRED`.

- **Salesforce:** UTF-8 object CSV and API field names are the Data Loader foundation. Parent relationship columns use the relationship name and an indexed field, for example `Account.MockMill_ID__c` only after the required field exists. Standard Salesforce IDs must come from the target. Data Import Wizard matching is a different route, not interchangeable with a universal Data Loader upsert claim. [Relationship/external-ID guidance](https://help.salesforce.com/s/articleView?id=000313396&language=en_US&type=1), [Wizard account/contact matching](https://help.salesforce.com/s/articleView?id=sf.for_accounts_and_contacts.htm&language=en_US&type=5).
- **HubSpot:** CSV/XLS/XLSX headers map to properties. Contacts require Email for this fixture's identification; companies use Company domain name; deals require Deal name, Pipeline and Deal stage. Existing records and associations need the appropriate Record ID, email/domain or supported custom unique property. Blank cells do not universally clear stored values. [File requirements](https://knowledge.hubspot.com/import-and-export/set-up-your-import-file), [object imports](https://knowledge.hubspot.com/import-and-export/import-objects).
- **Dynamics 365 / Dataverse:** The model-driven app import wizard accepts CSV and other documented formats. Updates must use a defined selected alternate key or actual identity. Lookup mapping and table-required fields are target-specific; no source string is a target GUID. [Import data](https://learn.microsoft.com/en-us/power-apps/user/import-data), [alternate-key references](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/use-alternate-key-reference-record).
- **Zoho CRM:** Module imports require appropriate fields, including Account Name, Contact Last Name and Deal Name/Closing Date plus layout requirements. Import Accounts before dependent modules. Account lookup may use a correctly matched name or genuine target ID. External-ID field update behavior has API-specific constraints; CSV replay relies on the actual permitted unique-field/module-ID mode. [Official import guidance](https://help.zoho.com/portal/en/kb/crm/data-administration/import-data/articles/import-data).
- **Pipedrive:** Spreadsheet rows can link people, organizations and deals. Person/organization identification and deal fields must be mapped. Updating existing items requires genuine Pipedrive System IDs. Synthetic provenance keys are distinct and cannot be substituted. [Spreadsheet import](https://support.pipedrive.com/en/article/importing-data-into-pipedrive-with-spreadsheets), [spreadsheet updates](https://support.pipedrive.com/en/article/updating-pipedrive-data-with-a-spreadsheet).

The starter scope is accounts/companies/organizations, contacts/people and opportunities/deals. Required custom markers, unique keys, existing pipeline/stage values, ownership, edition limits, duplicate policies and side-effect controls need a target-specific review. CSV values using reserved domains are safe fictional examples; their acceptance by every target validator has not been demonstrated.
